# adaC compiler architecture

The repository layout follows the one used by `rust-lang/rust` (see the *rustc-dev-guide*,
"High-level overview of the compiler source"): the compiler is split into small, single-purpose
**crates** under `compiler/`, the standard library lives in its own tree `library/`, helper tools live
in `src/`, and the test-suite lives in `tests/`.

```
adac/
├── compiler/                  the compiler, one directory ("crate") per stage
│   ├── common.h               umbrella header shared by every stage
│   ├── adac_data_structures/  Vec, memory helpers                        (rustc_data_structures)
│   ├── adac_span/             source files and locations                  (rustc_span)
│   ├── adac_errors/           diagnostics with source snippets            (rustc_errors)
│   ├── adac_lexer/            text -> tokens                              (rustc_lexer)
│   ├── adac_ast/              syntax tree, types, symbols                 (rustc_ast / rustc_middle)
│   ├── adac_parse/            tokens -> AST                               (rustc_parse)
│   ├── adac_analysis/         names, types, classes, checks, rewriting    (rustc_hir_analysis + lowering)
│   ├── adac_codegen/          AST -> x86-64 machine code (+ encoder)      (rustc_codegen_*)
│   ├── adac_link/             writes the Windows PE32+ executable         (the linker step)
│   └── adac_driver/           command line, `use` resolution, pipeline    (rustc_driver / rustc_interface)
├── library/                   the standard library, written in adaC
│   ├── MODULES                registry: which file is always loaded / optional
│   ├── core/                  no heap, no OS: math, char, str, num, fmt, error, option, result
│   ├── alloc/                 needs the heap: string, collections, boxed, rc, allocators
│   └── std/                   needs the OS: sys, io, time, fs
├── src/tools/embed/           build tool that embeds library/ into the compiler binary
├── editors/vscode/            VS Code extension (highlighting, live diagnostics, snippets)
├── tests/                     harness/, ui/ (run-pass, compile-fail, compile-pass), library/
├── examples/                  programs (and examples/bin: prebuilt .exe files)
├── benchmarks/                C vs adaC vs Python
├── docs/                      this documentation
└── build/                     generated by the build (object files, library_data.c)  — git-ignored
```

## Pipeline

```
.adac source ─► adac_lexer ─► adac_parse ─► adac_analysis ─► adac_codegen ─► adac_link ─► program.exe
                                  ▲                ▲
              library/ (embedded) ┴── `use` ───────┘   the library is parsed and analysed together with the program
```

1. **Driver** (`adac_driver`): loads the program and its `import "file";` modules, decides the memory
   mode (`#NOT_GARBAGE`), resolves `use` declarations against `library/MODULES`, selects the library
   modules (always-loaded prelude + allocator for the mode + requested optional modules).
2. **Lexer / parser**: library and program are parsed with the same code. The library is flagged
   `is_prelude`, which enables the intrinsics (`__winapi`, `__peek64`, ...) only there.
3. **Analysis** (`adac_analysis/sema.c`): collects classes (inheritance, vtables, interface tables,
   generics), functions and globals; type-checks; rewrites `print`, `printf`, string `+`, `list[i]`,
   `for-each`... into calls to library functions.
4. **Code generation**: a simple stack-machine style generator; `x64.c` encodes instructions.
5. **Link**: `pe.c` lays out `.text`, `.data`, `.idata` and writes the `.exe` (imports `KERNEL32.dll`).

## How the library reaches the compiler

`library/MODULES` lists every library file with a *kind*:

| kind | meaning |
|---|---|
| `always` | part of the prelude: compiled into every program |
| `gc` / `manual` | the allocator, chosen by `#NOT_GARBAGE` |
| `opt` | compiled only when the program (or another module) says `use <path>;` |

`src/tools/embed` turns those files into `build/library_data.c`, an array of `{kind, path, text}` linked
into `adac`. The compiler therefore needs no files besides itself at run time.

## Rust ↔ adaC at a glance

| Rust | adaC |
|---|---|
| `compiler/rustc_*` crates | `compiler/adac_*` directories |
| `library/{core,alloc,std}` | `library/{core,alloc,std}` |
| `use std::collections::HashMap;` | `use std::collections::Stack;` (selects the library module) |
| `Vec<T>`, `HashMap<K,V>`, `Option<T>`, `Result<T,E>`, `Box<T>`, `Rc<T>`, `String` | `List<T>`, `Map<String,V>`, `Option<T>`, `Result<T>`, `Box<T>`, `Rc<T>`, `StringBuilder` |
| `x.py` / cargo build | `make` / `build.bat` |
| `tests/ui/*.rs` with `//~ ERROR` | `tests/ui/**/*.adac` with `// error-pattern:` |
